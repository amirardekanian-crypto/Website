### Leads → Chats — the website chatbot's saved conversations (2026-10-17)

`#leads/chats`. What people asked the site's chatbot, from `chat_conversations` and `chat_messages` (`supabase/stage67_site_chat.sql`; only the `site-chat` Edge Function writes them, the coach can read and delete, RLS through `is_coach()`). Both tables are in `BACKUP_TABLES`. It is loaded when the tab first opens, not at boot: `chatsLoad()` first deletes conversations whose `last_at` is older than 90 days (quietly; their messages go by `ON DELETE CASCADE`), then reads the rest with `selectAll()`; a failed read lands in `LOAD_ERR.chats` and the tab offers Try again. The layout is Applications': the list on the left (date and time, an EN/FA pill, the visitor's first message, the turns, a WhatsApp or Apply tag when the chat ended in a handoff), the chosen chat on the right as a transcript (visitor text escaped, `dir="auto"` for Farsi), its page and its cost (`cost_usd`, 4 decimals); below 1000 px the list is the screen. The top line totals this month's chats and cost. **Delete this chat** goes through `dangerAsk()` and writes with `.select()` + `writeFailed()`. Harness scenario: `leads-chats`. **Not answered yet** (stage68, 2026-10-17): the top of the tab lists every assistant reply with `chat_messages.gap = true` (the `site-chat` function sets it when the facts file, `Content/CHATBOT-FACTS.md`, could not answer) and `gap_handled_at` null, newest first, each with the visitor's question, the trimmed reply, an **Open chat** link and **Added to facts ✓**, which writes only `gap_handled_at` (the one column the coach may update; `.select()` + `writeFailed()`, with the one-tap Undo bar). Conversations with an open gap carry a plum *Not in your facts* pill in the list, the transcript marks the reply, and the **Only with gaps** chip filters the list; the count is not in Today's *Also waiting* (chats load only when the tab opens). Harness scenario: `leads-chats-gaps`.
