# Article publisher — AA Performance Read library + the website

One article, three places, every time (Amir, 2026-09-13: *"every time I add an article it
updates the website as well"*):

1. **The app** — `articles/<category>/<slug>.json`, English, published to `public.library`
   from coach.html. Opens at `program.html?article=<slug>`.
2. **The Farsi website** — `/fa/articles/<slug>.html`, built from a reviewed Farsi translation
   `articles/<category>/<slug>.fa.json`. **This is the page people in Iran find on Google.**
3. **The English website** — `/en/articles/<slug>.html`, built from the English JSON.

Pages 2 and 3, both index pages and `sitemap.xml` are generated by
`scripts/build_article_pages.py`. **Never hand-edit anything under `en/articles/` or
`fa/articles/`** — the next build overwrites it. `.githooks/pre-commit` blocks any commit
where the pages are stale or the Farsi is missing, so skipping a step fails loudly.

## Step 0 — Required reading (every run)

1. **`SCHEMA.md` → "Library tab — Read section"** — block types, manifest format, icon keys, category list.
2. **`Content/PRODUCT.md`** — what the product is, who the audience is, what the voice sounds like. The English article is sharp and evidence-based (same voice as the English website).
3. **`Content/DESIGN_SYSTEM.md` §10** — the Farsi word choices (for Step 6).
4. **`.claude/SEO-SOP.md`** — how titles and descriptions are chosen so the page can be found.

## Step 1 — Understand what you've been given

Amir will either:
- **Paste finished copy** — your job is to map it faithfully to blocks, not rewrite it. Clean up formatting only.
- **Give a topic or outline** — write the article yourself. Use his coaching voice: direct, no fluff, grounded in physiology. Short paragraphs. No hedging. Make claims and back them up.
- **Somewhere between** — treat his text as raw material, tighten where needed, keep his meaning and any specific numbers/names.
- **Revise an existing article** — edit the English JSON, then Steps 6–9 still apply: the Farsi must be updated to match before anything ships (the build calls it "out of date" until it is).

Identify:
- **Category** — one of: `for-coaches`, `pre-competition`, `recovery`, `mental`, `nutrition`, `supplements`. Ask if genuinely unclear.
- **Slug** — short, lowercase, hyphenated, descriptive (e.g. `pre-session-warm-up`, `zone-2-for-tennis`). It becomes the web address, so it stays English and stable — never rename a published one.
- **Title** — clean, confident, no clickbait. The **last word gets a clay highlight** in the hero — pick a title where the last word lands well visually (a strong noun or verb, not "a" or "the").
- **Read time** — roughly 200 words per minute. Round to nearest minute.

## Step 2 — Map the text to blocks

Every article is an array of `blocks`. Map the text in order:

### `p` — paragraph
Plain prose. The **first `p` block** gets a large clay drop-cap on its first letter automatically — open with a punchy sentence whose first letter reads well large (M, T, W, H, A all look strong; avoid I, a, or punctuation).

```json
{ "type": "p", "text": "Most players jog a lap and call it a warm-up." }
```

### `h` — section heading
Used for major topic shifts. **Do not number them** — the app auto-adds §01, §02… Keep headings short and active. Every `h` gets a leading clay dash automatically.

```json
{ "type": "h", "text": "Why warming up matters" }
```

### `list` — bullet list
For 3+ parallel items. Each item gets a clay tennis-ball bullet. Keep items parallel in structure. Not for steps — use callouts for steps.

```json
{ "type": "list", "items": ["Point one", "Point two", "Point three"] }
```

### `callout` — labelled box
Clay-tinted box with a short label badge at the top. Use for:
- **Rules / key principles** — label: `"Rule"`, `"Key"`, `"Remember"`
- **Steps in a sequence** — label: `"Step 1 — Raise"`, `"Step 2 — Mobilise"` etc.
- **Named protocols** — label: the protocol name
- **Warnings / watch-outs** — label: `"Watch Out"`, `"Avoid"`

Keep `label` short (1–4 words). The `text` can be a full paragraph.

```json
{ "type": "callout", "label": "Rule", "text": "Move, don't hold. Everything in your warm-up should be moving." }
```

### `img` — image
Only use if Amir provides an image path or asks for one. Caption is optional.

```json
{ "type": "img", "src": "assets/img/example.webp", "caption": "Optional caption text." }
```

### `workout` — embedded workout card
Links to an existing workout in the Train library. Only use if a matching workout exists in `workouts/index.json`. Tapping opens the full workout session (on the website it links to `program.html?workout=<id>`).

```json
{ "type": "workout", "file": "workouts/on-court/tennis-warm-up-routine.json", "label": "Tennis Warm-Up Routine", "meta": "12–15 min · Bodyweight · On-Court" }
```

## Step 3 — Write the article JSON

Create **`articles/<category-id>/<slug>.json`**:

```json
{
  "id": "<slug>",
  "title": "<Title>",
  "category": "<Category display name>",
  "readMins": <number>,
  "date": "<Month YYYY>",
  "blocks": [ … ]
}
```

`category` is the display name (e.g. `"For Coaches"`), not the ID (e.g. `"for-coaches"`).
`date` must be `"<Month> <YYYY>"` in English (e.g. `"September 2026"`) — the web pages read it.

## Step 4 — Register in the manifest

Read `articles/index.json`, find the right category by `id`, and add to its `articles` array:

```json
{
  "id": "<slug>",
  "title": "<Title>",
  "category": "<Category display name>",
  "readMins": <number>,
  "file": "articles/<category-id>/<slug>.json"
}
```

If the category doesn't exist yet, add it with the right `icon` key (see SCHEMA.md → current category table) and an empty `articles` array, then add the entry. **A new category also needs its English + Farsi names in `CATEGORIES` at the top of `scripts/build_article_pages.py`** — ask Amir for the Farsi name.

## Step 5 — Verify the JSON is valid

Before going on:
- Valid JSON (no trailing commas, no comments)
- `id` in the article file matches the slug used in the manifest `file` path
- `file` path in the manifest exactly matches the file you created
- `category` display name is consistent between article file and manifest entry

## Step 6 — Write the Farsi translation (for the website)

Create **`articles/<category-id>/<slug>.fa.json`** next to the English file:

```json
{
  "_note": "Website-only Farsi copy of <slug>.json. No id/category on purpose: coach.html's Publish article must refuse this file. Pages: python scripts/build_article_pages.py",
  "translationOf": "<slug>",
  "lang": "fa",
  "sourceHash": "",
  "title": "<Farsi title>",
  "seoTitle": "<Farsi title for Google> | امیر اردکانیان",
  "description": "<Farsi meta description>",
  "blocks": [ … ]
}
```

⚠️ **Never give this file an `"id"` or a `"category"`.** coach.html's *+ Publish article* accepts
any file that has both and upserts it by slug — a Farsi file with them would overwrite the English
article in the app for every athlete. The build refuses such a file for exactly that reason.

**Block for block.** Same number of blocks, same order, same `type` each, same number of list
items. A `workout` block keeps its English `file` and translates `label` and `meta`. The build
checks all of this.

**Translate faithfully.** Never add, drop, soften or strengthen a claim. Every number, percentage
and study result stays exactly as the English says it — Amir holds an exercise-physiology ارشد
and fact-checks.

**Voice and typography** — the Farsi website voice: warm, direct, colloquial Tehrani (`می‌کنه`,
`نمی‌تونه`, `یه`), per `Content/DESIGN_SYSTEM.md` §10 (`شدت` not `سختی`, `ارشد` never "MSc",
`شروع کن` not `درخواست`). Then:
- **Persian digits** everywhere in the text (`۱۰ تا ۱۵ دقیقه`, `۴٫۶`), Persian `ی` and `ک` (never Arabic `ي` `ك`).
- **Half-space (ZWNJ, U+200C)** in `می‌`/`نمی‌` verbs, plurals (`تمرین‌ها`) and compounds (`گرم‌کردن`). No `می ` with a normal space.
- «گیومه» for quotes, never `"`. No em-dash chains — use `:` `؛` `،` the way Farsi prose does.
- Exercise names people know in English: transliterate, with a short Farsi gloss the first time (`پلِ باسن (گلوت بریج)`).

**Title, seoTitle, description** — these decide whether the page is found (`.claude/SEO-SOP.md`):
- `title`: the Farsi phrase a player would actually type into Google (`گرم‌کردنِ قبل از تنیس`), not a literal translation of a clever English title.
- `seoTitle`: under ~65 characters including ` | امیر اردکانیان`; the search phrase first.
- `description`: 120–160 characters, says what the reader gets.

Run the lint, then **show Amir the Farsi — title, seoTitle, description and the full text — and
WAIT for his OK.** He is the native speaker and the coach of record; nothing Farsi ships unread.

```
PYTHONIOENCODING=utf-8 python -c "import json,re,sys;t=open(sys.argv[1],encoding='utf-8').read();json.loads(t);print('arabic yk',len(re.findall('[يك]',t)),'| mi+space',len(re.findall(r'(?:^|[\s«(])ن?می \S',t)))" articles/<category-id>/<slug>.fa.json
```

After his OK, record that the Farsi matches this version of the English:

```
python scripts/build_article_pages.py --stamp <slug>
```

## Block sequencing rules

Good articles follow this rhythm — adapt freely, but don't over-structure:

| Opening | 2–3 `p` blocks. Hook → tension → what this article solves. First `p` = drop-cap. |
|---|---|
| Body sections | `h` → supporting `p` → `list` or `callout` as needed. One idea per section. |
| Callout placement | At the end of a section to crystallise the point, or as a step sequence. |
| Closing | One final `h` + a `callout` with label `"Rule"` or `"Key"` works well as a payoff beat. |

## Writing standards (when writing the article yourself)

- **Direct.** State the claim, then back it up. Not: "It might be worth considering…" — Yes: "Stop holding stretches before training."
- **Short paragraphs.** 2–4 sentences max. One idea per paragraph.
- **Evidence-based.** Any percentage, study result, or physiological claim must be accurate. If unsure, soften to a defensible round figure or flag it.
- **No hedging.** No "arguably", "some might say", "in some cases". Be a coach, not a committee.
- **English in the app.** The Read library is the English-language app experience; the Farsi translation (Step 6) exists for the website only.
